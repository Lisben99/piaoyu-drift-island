# 漂屿“共鸣广场”与梦境灵魂全站视觉设计

日期：2026-08-11  
状态：已确认视觉与产品方向，待实施计划  
范围：用户端网站；管理后台不改版

## 1. 背景与目标

现有“漂流大厅”和“社区”都采用陌生人内容卡片、互动、私聊的路径，用户感知差异不足。改造后，两者承担不同的社交任务：

- 漂流大厅：匿名、短暂、随机的内容相遇。
- 共鸣广场：稳定人格、兴趣表达和长期关系沉淀。
- 消息：已经建立的私聊关系。
- 我的：人格、兴趣、等级和内容资产。

本项目采用 Soul 式“先内容共鸣、后认识用户”的社区路径，不以距离、真人照片或恋爱匹配为第一入口。

### 成功标准

- 用户能一眼区分大厅与共鸣广场。
- 用户能通过兴趣、话题和内容发现同频的人。
- 共鸣、评论、关注和私聊形成清晰的关系递进路径。
- 全部用户端页面使用统一的“梦境灵魂”视觉语言。
- 现有用户、动态、关注、点赞、评论和等级数据可继续使用。
- 移动端 360、375、390、430px 竖屏无横向溢出、裁切和安全区遮挡。

## 2. 非目标

第一阶段不实现：

- 短视频、直播和礼物打赏。
- 语音匹配、语音房和群聊房。
- 复杂性格测试与契合度计算。
- AI 推荐模型；第一阶段使用可解释规则排序。
- 强制真人头像、精确位置展示或左右滑恋爱匹配。
- 管理后台视觉重构。

## 3. 用户端信息架构

五个主导航调整为：

1. 首页：签到、等级进度、个人状态和快捷入口。
2. 大厅：随机漂流瓶与匿名交流。
3. 共鸣：兴趣内容、话题表达和关系沉淀。
4. 消息：私聊与互动通知。
5. 我的：人格资料、兴趣、等级和内容资产。

原“社区”导航名称改为“共鸣”，页面标题改为“共鸣广场”。

## 4. 共鸣广场页面结构

页面从上到下依次为：

1. 顶部栏：标题、搜索、发布。
2. 主分类：为你推荐、最新、关注。
3. 兴趣标签：横向滚动的内容过滤器。
4. 每日话题：低门槛表达入口。
5. 内容流：人格身份、话题、正文、图片和互动。
6. 主导航：共鸣为激活状态。

### 4.1 为你推荐

基于用户兴趣、历史共鸣、评论行为、关注关系、内容时间和安全质量排序。没有行为数据的新用户优先看到最新的高质量内容、热门兴趣和每日话题。

第一阶段建议权重：

- 兴趣匹配：35%。
- 用户互动偏好：25%。
- 内容新鲜度：25%。
- 内容质量与安全：15%。

推荐结果必须排除被屏蔽用户、已删除内容和审核不通过内容，并降低短时间内重复作者的比例。

### 4.2 最新

所有审核通过的公开社区动态按时间倒序，不混入私人朋友圈动态。

### 4.3 关注

只显示已关注用户发布的公开社区动态。取消关注后即时从该列表移除，空状态引导用户前往推荐或最新发现用户。

## 5. 兴趣身份

用户首次进入共鸣广场时展示轻量兴趣选择：

- 推荐选择至少 3 个，但允许跳过。
- 初期提供 10–15 个受控分类，避免内容池过度分散。
- 初始分类：音乐、电影、阅读、摄影、旅行、独处、情绪、城市漫游、宠物、游戏、运动、美食。
- 用户可在编辑资料中随时调整。
- 个人主页最多展示 5 个代表性兴趣。

推荐和话题过滤只使用受控兴趣 ID，前端展示名称由服务器配置返回，避免客户端与后端分类不一致。

## 6. 发布动态

第一阶段支持：

- 文字。
- 最多 9 张图片。
- 可选一个受控话题。
- 可选当前心情。
- 参与每日话题。

建议心情枚举：开心、平静、低落、迷茫、期待、疲惫、治愈。

发布流程：

1. 输入文字和选择图片。
2. 选择心情。
3. 选择话题或自动带入每日话题。
4. 提交审核。
5. 发布成功后返回共鸣广场，并在合适位置展示经验获得提示。

内容为空、图片上传失败、审核失败和网络错误都必须保留用户尚未提交的草稿。

## 7. 动态卡片与互动

### 7.1 身份区

动态顶部固定展示：

- 虚拟头像或用户头像。
- 昵称。
- 性别 SVG 图标。
- 认证徽章。
- 等级徽章。
- 发布时间和所属话题。
- 关注按钮；自己的内容不显示关注。

昵称可以截断，性别、认证和等级保持固定尺寸并紧邻昵称，不得被右侧操作按钮推离头像区域。

### 7.2 内容区

- 正文完整换行，长文可折叠为“展开全文”。
- 图片使用 1、2、3–9 张自适应网格。
- 心情与话题使用低对比标签，不抢夺正文视觉层级。

### 7.3 操作区

第一阶段只保留三种主要行为：

- 共鸣：由现有点赞行为升级，保留历史点赞数据。
- 评论：支持一级回复和提及用户。
- 聊聊：打开打招呼面板，然后进入私聊。

关注仍位于身份区。自己的动态在底部最右显示三点菜单，提供编辑和删除；他人的三点菜单提供不感兴趣、举报和屏蔽。

### 7.4 聊聊面板

点击“聊聊”后先展示轻量面板，而不是直接进入空白聊天：

- 根据动态类型显示 3 条固定模板。
- 用户可以编辑模板或输入自己的开场白。
- 发送前继续执行当前私聊权限、漂流币和封禁规则。
- 发送成功后进入聊天页面。

示例：

- 我也有过类似的感受。
- 你照片里的地方是哪里？
- 最近还有什么歌推荐吗？

## 8. 每日话题与话题页

每日话题由管理配置或预设轮换产生，包含：

- 标题、引导语和有效日期。
- 参与人数。
- 关联兴趣分类。
- 审核状态。

点击每日话题直接打开发布页并预选该话题。

普通话题页包含：

- 话题简介。
- 参与人数。
- 热门动态。
- 最新动态。
- 参与发布按钮。

第一阶段不允许用户自由创建新话题，只能选择受控话题，降低空话题、重复话题和违规内容成本。

## 9. 搜索

顶部搜索覆盖：

- 用户昵称。
- 受控话题。
- 公开社区动态正文。

搜索页展示热门话题和最近搜索。搜索结果按用户、话题、动态分组，不搜索私人朋友圈和聊天内容。

## 10. 人格主页

他人主页重点展示：

- 头像、昵称、性别、等级和认证。
- 个性签名。
- 兴趣标签。
- 关注数、粉丝数、获得共鸣数。
- 公开社区动态。
- 关注与聊聊按钮。

真人照片可以出现在动态中，但不强制作为头像。私人朋友圈继续遵守既有聊天关系可见性规则，不与公开社区动态混合。

## 11. 安全与隐私

动态三点菜单：

- 他人动态：不感兴趣、举报、屏蔽用户。
- 自己动态：编辑、删除。

私聊权限：

- 所有人可以打招呼。
- 仅允许关注我的人。
- 关闭陌生人私聊。

安全规则：

- 被屏蔽用户不进入推荐、关注流、评论和私聊。
- 发布、评论和开场白都经过现有内容审核。
- 举报沿用现有举报流程并记录来源内容。
- 对发布、评论、共鸣、关注和打招呼设置速率限制。
- 精确位置不进入公开社区数据。

## 12. 等级系统结合

新增或调整经验来源：

- 每日首次发布通过审核的社区动态。
- 收到不同真实用户的有效共鸣。
- 收到真实评论。
- 参与每日话题。
- 连续活跃。

同一用户的重复互动不重复奖励；每天设置总上限。取消共鸣、删除内容或审核撤回时，第一阶段不追扣已经发放的少量经验，但相关事件必须幂等，防止重复入账。

## 13. 梦境灵魂视觉系统

### 13.1 核心色

- 主色：`#7561D1`，用于主按钮、激活导航和核心状态。
- 主色深阶：`#5947B4`，用于按压状态与高对比文本。
- 情绪粉：`#C878B7`，用于渐变终点、情绪与轻量强调。
- 页面背景：`#F7F5FC`。
- 主正文：`#28243D`。
- 次级文字：`#8F899F`。
- 危险操作：`#E5747D`。
- 等级金：`#DDA95E`。
- 成功状态：`#59A994`，只用于成功反馈，不作为品牌主色。

### 13.2 表面与渐变

- 页面使用极浅紫背景，可在顶部使用低透明度紫粉径向渐变。
- 内容卡片使用 84%–92% 白色表面和低强度阴影。
- 玻璃效果只用于顶部栏、底栏和少量主卡片，不叠加到所有内容。
- 主按钮使用紫到粉紫渐变，危险按钮保持纯珊瑚红。
- 保持足够对比度，正文不使用浅紫色。

### 13.3 组件规范

- 大卡片圆角：16–20px。
- 小卡片和输入框圆角：12–14px。
- 胶囊按钮圆角：999px。
- 头像：圆形；个人主页主头像允许使用 18–22px 圆角方形，形成 Soul 式人格感。
- 阴影：紫色低透明阴影，避免厚重黑影。
- 图标：统一线性 SVG，激活态使用主紫色。
- 动效：150–220ms；只使用淡入、轻微缩放和位移，不使用高频闪烁。

### 13.4 无障碍

- 正文与背景对比度不低于 WCAG AA。
- 颜色不能作为唯一状态提示，必须同时提供文字或图标。
- 触控目标建议不小于 44×44px。
- 尊重 `prefers-reduced-motion`。

## 14. 全站用户端页面覆盖

以下页面统一换用梦境灵魂主题：

- 欢迎、登录、注册、角色选择、协议。
- 首页。
- 漂流大厅、发布漂流瓶、我的瓶子。
- 共鸣广场、发布动态、搜索、话题页。
- 通知、消息列表、聊天。
- 他人主页、朋友圈。
- 我的、编辑资料、等级详情。
- 漂流币、充值、邀请、黑名单、举报、客服、注销。

管理后台维持现有高对比视觉，只复用必要的状态色语义，不引入玻璃与渐变风格。

## 15. 数据模型与接口

### 15.1 用户

新增或规范：

- `interestIds: string[]`
- `strangerChatPolicy: 'all' | 'followers' | 'closed'`

### 15.2 公开社区动态

在现有公开社区动态记录上新增：

- `topicId: string | null`
- `mood: string | null`
- `dailyPromptId: string | null`
- `editedAt: number | null`

现有 `likes` 数组继续保存互动用户 ID，API 和 UI 对外命名为“共鸣”，避免数据迁移风险。

### 15.3 评论

新增可选 `parentCommentId`，只允许一级回复。接口返回被回复用户的昵称和 ID，删除父评论时子回复保留但显示“原评论已删除”。

### 15.4 新集合

- `communityTopics`：受控话题与兴趣映射。
- `dailyPrompts`：每日问题与日期。
- `contentDismissals`：不感兴趣记录。

### 15.5 接口方向

- `GET /api/community/topics`
- `GET /api/community/prompts/today`
- `GET /api/moments/community?sort=recommend|latest|following&topicId=`
- `GET /api/community/search?q=`
- `POST /api/moments/:id/dismiss`
- `PUT /api/moments/:id`
- `PATCH /api/profile/interests`
- `PATCH /api/profile/chat-policy`

现有接口保持兼容；缺少新字段的历史动态按 `null` 处理。

## 16. 状态与错误处理

每个新页面必须覆盖：

- 首次加载骨架屏。
- 空数据状态。
- 网络错误与重试。
- 内容审核中和审核失败。
- 图片上传部分失败。
- 长昵称、多徽章、长文、多图和 99+ 未读。
- 被屏蔽、被删除和权限不足。

推荐接口失败时降级到最新内容；每日话题接口失败时隐藏话题卡，不阻断内容流。

## 17. 迁移与发布

建议分三批实施：

### 第一批：设计系统与现有页面换肤

- 建立 CSS 变量、按钮、卡片、输入框、弹窗、顶部栏和底栏规范。
- 完成全部用户端页面主题切换。
- 不改变后台数据。

### 第二批：共鸣广场核心功能

- 社区改名。
- 兴趣选择、受控话题、心情、每日话题。
- 共鸣语义、三种内容流、搜索和聊聊面板。
- 公开主页兴趣与获得共鸣统计。

### 第三批：安全、排序与质量优化

- 不感兴趣、屏蔽联动和私聊权限。
- 推荐权重调优。
- 经验规则和反刷限制。
- 真实移动端全链路回归。

每批单独提交、验证和部署，避免同时修改全站主题、数据模型和推荐逻辑。

## 18. 验收标准

- 大厅和共鸣广场在信息结构、文案和视觉上可以立即区分。
- 用户可选择兴趣、参与话题、发布带心情和话题的动态。
- 推荐、最新、关注三种内容流均返回正确内容。
- 历史点赞数据以共鸣数量正常显示。
- 关注、评论、聊聊、举报、屏蔽和删除链路可用。
- 私人朋友圈不进入公开社区搜索和推荐。
- 全部用户端页面使用统一主题变量，无遗留大面积海绿色主按钮。
- 360、375、390、430px 竖屏无横向滚动、控件裁切和安全区遮挡。
- 软键盘不遮挡发布、评论、搜索和聊天输入框。
- 推荐失败可降级，网络错误可重试，草稿不会因失败丢失。

## 19. 已确认决策

- 产品方向：Soul 式兴趣内容社区。
- 身份模式：半匿名人格化，真人照片可选。
- 社区名称：共鸣；页面名称：共鸣广场。
- 功能范围：UI 重构加核心社区能力，不做完整 Soul 功能集合。
- 视觉方向：梦境灵魂；紫蓝主色、粉紫点缀、轻玻璃卡片。
- 换肤范围：全部用户端页面；管理后台保持现状。
- 数据策略：渐进式扩展并保留现有数据。
