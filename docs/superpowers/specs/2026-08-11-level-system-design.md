# 漂屿等级系统设计

日期：2026-08-11  
状态：已确认，待实施

## 目标

把当前分散且不一致的等级计算改成后端统一的经验流水制，并完成“我的”经验进度、等级详情、升级提示以及社区/资料页徽章的一致展示。系统鼓励真实互动，不允许通过重复请求或无限刷低质量内容快速升级。

## 现状与方案选择

现有 `computeUserLevel()` 按动态、瓶子、聊天、注册天数和余额实时推算经验；“我的”页面又使用 `momentCount / 5` 单独计算，两个来源会产生不同等级。

评估过三种方式：

1. **经验流水制（采用）**：每次有效行为写入可追踪流水，支持去重、每日上限和经验记录；改动较多，但规则稳定、可解释、可防刷。
2. 继续实时推算：改动最少，但删除内容、余额变化或时间增长会改变等级，无法解释经验来源。
3. 只在用户记录保存一个经验总数：实现简单，但缺少幂等、防刷和审计能力。

生产仍沿用当前 JSON/PostgreSQL `kv_store` 整体文档存储，不新增独立 SQL 表。本轮只在数据库文档增加 `experienceEvents` 集合及用户迁移字段。

## 等级规则

| 等级 | 称号 | 累计经验 |
|---|---|---:|
| Lv.1 | 初到海岸 | 0 |
| Lv.2 | 拾贝者 | 20 |
| Lv.3 | 漂流者 | 60 |
| Lv.4 | 灯塔守望者 | 120 |
| Lv.5 | 群岛旅人 | 220 |
| Lv.6 | 潮汐信使 | 360 |
| Lv.7 | 深海回声 | 550 |
| Lv.8 | 星海航行者 | 800 |
| Lv.9 | 群岛领航员 | 1120 |
| Lv.10 | 漂屿传说 | 1500 |

满级继续累计经验，等级进度显示为 100%。

## 经验事件与限制

| 行为 | 单次经验 | 限制 |
|---|---:|---|
| 每日首次签到 | +2 | 每天一次 |
| 完善个人资料 | +10 | 每个用户一次 |
| 发布漂流瓶 | +2 | 每天最多 3 次计分 |
| 有效回复漂流瓶 | +3 | 每天最多 5 次计分 |
| 发布社区动态 | +3 | 每天最多 2 次计分 |
| 有效评论 | +1 | 每天最多 5 次计分 |
| 收到他人点赞 | +1 | 每天最多 5 次计分；自己点赞、取消后重赞不重复计分 |
| 举报内容被管理员确认有效 | +2 | 每天最多 3 次计分 |

连续签到第 3、7、14、30 天分别额外获得 2、5、10、20 经验。漂流币签到周期保持原逻辑，另存连续经验签到天数，避免改变现有货币奖励。

每条经验流水包含唯一 `eventKey`。同一业务事件因网络重试再次提交时返回原结果，不重复加分。达到每日上限时业务操作继续成功，只是不再增加经验。

## 旧用户迁移

新用户从 0 经验开始。旧用户首次加载新版本数据库时，根据旧 `computeUserLevel()` 的贡献公式生成一次性 `experienceBase`，并写入迁移时间。此基线之后固定，不因删除内容、余额变化或注册天数增加而变化；新经验只来自流水。这样上线后不会造成已有用户突然掉级。

## 后端边界与接口

数据库模块提供：

- `awardExperience(userId, type, options)`：验证事件、幂等和每日上限，写入流水，返回增加值及升级结果。
- `getUserLevel(userOrId)`：返回 `level`、`title`、`exp`、`currentExp`、`nextExp`、`progress`、`maxLevel`。
- `getExperienceHistory(userId, limit)`：只返回该用户最近的经验流水。

`GET /api/auth/me` 和公开资料接口统一返回后端等级摘要。新增 `GET /api/profile/level/me` 返回当前用户等级、等级表、经验规则和最近流水。创建瓶子、回复、发布动态、评论、点赞、签到、完善资料以及管理员确认举报时触发对应事件。

升级信息随原业务响应返回。一次请求失败或经验记录失败不能把主要业务伪装成成功；经验达到上限则明确返回 `awarded: 0` 和原因。

## 前端体验

- “我的”资料卡不再自行推算等级，显示后端 `Lv.x`、称号和经验进度条。
- 点击经验区域进入等级详情页；页面展示当前进度、距离下一级经验、十级称号、经验规则和最近记录。
- `api()` 统一识别业务响应中的升级结果，只弹一次轻量升级提示；普通加经验不频繁弹窗。
- 社区、关注列表、附近的人、公开资料以及“我的”统一使用同一等级徽章组件。
- 长昵称优先截断，性别、认证和等级徽章保持固定尺寸且不换行。
- 无数据、网络失败和满级都有明确状态；移动端安全区与独立滚动规则沿用现有实现。

## 非目标

- 本轮不提供付费买经验、不按等级提高推荐曝光、不增加排行榜。
- 不重构整个单文件前端，不改变管理后台的整体视觉。
- 不调整漂流币数值和收费逻辑。

## 验收

- 所有页面对同一用户显示相同等级与称号。
- 事件重试、取消后重赞、自己点赞和超过每日上限均不会重复计分。
- 旧用户迁移后等级不低于上线前计算结果，新用户从 Lv.1 开始。
- “我的”与等级详情正确显示 0 经验、升级中、满级和网络错误。
- 360、375、390、430px 下经验卡、等级徽章和长昵称无横向溢出。
- 现有社交、瓶子、签到、资料编辑和举报处理行为保持可用。
